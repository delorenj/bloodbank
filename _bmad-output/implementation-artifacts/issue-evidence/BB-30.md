### Durable semantics

- Native finalizer validates and commits immutable optional answer bytes in
  `captured_events` with explicit model `capture_outcome`. The row remains
  `started`, final `outcome` NULL, terminal outbox empty. No publication is
  possible from capture alone. This retains the original crash/no-rerun boundary.
- Processing-complete resolves platform outcome, combines native failed/
  interrupted status and existing refusal/shutdown policy, then commits the
  final outbox. Only full success admits the unchanged captured answer. Actual
  failure/cancellation/timeout/interruption excludes it. Terminal creation now
  shares the existing model override / detached annotation path, and shutdown
  stores `failure_code=interrupted_by_shutdown` before publication.
- Unknown pending capture on restart resolves to explicit failure code
  `processing_outcome_unknown`, not success: no answer, no inference. Original
  capture bytes survive for audit. This deliberately loses answer availability
  if the final processing decision was not committed; it does not pretend the
  missing outcome was observed. A capture also disables pre-capture shutdown
  `retry` behavior, so no subsequent process reruns it.
- Contradictory callbacks poison pending capture durably with
  `conflicting_native_capture`. First body/time/identity remain immutable;
  restart publishes only failed closure. This also addresses the historical
  synthetic post-end conflict caveat without inventing new native ordering.
- Journal version 4 adds nullable capture columns in place and preserves old
  outbox bytes and lane/failure/detached metadata. Older source rejects v4;
  never lower the version to force an unsafe rollback. Only temporary test
  journals were upgraded; no production state was accessed.
- Final outbox publication still awaits answer (when eligible), invocation and
  turn PubAcks before command ACK. Publication/ACK failure replays exactly the
  resolved batch, without Hermes. Pre-capture process loss remains ambiguous.
